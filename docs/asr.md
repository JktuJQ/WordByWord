# Локальное распознавание

Импортированная запись проходит через готовый `AndroidAudioPreparer`, Silero VAD
и GigaAM v2 int8 в sherpa-onnx 2.0.1. Обработка работает в существующем фоновом
конвейере, текст отображается на обычном экране стенограммы. Демопример сохранён.
Отдельное приложение `experiments/asr-probe` удалено.
Проверен и обычный путь: выбор FLAC через системный проводник → «Обработать» →
экран с реальным текстом и таймкодами.

Участники пока неизвестны: диаризация не подключается в #5. Таймкоды относятся
к речевым фрагментам (`Timing.SEGMENT`), не к словам. VAD получает по 200 мс
контекста; соседние окна разделены, чтобы не распознавать одни отсчёты дважды.
Весь PCM в память не загружается, за один вызов распознаётся одно VAD-окно.
Отмена проверяется между чтениями и вызовами JNI; один `decode` не прерывается.

## Установка моделей

Модели устанавливаются заранее, интернет при распознавании не нужен.
Скачать в одну папку:

- [GigaAM v2, около 165 МиБ архивом](https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-nemo-transducer-giga-am-v2-russian-2025-04-19.tar.bz2).
- [Silero VAD, 629 КиБ](https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/silero_vad.onnx).
- [Android AAR, 49 МБ](https://github.com/k2-fsa/sherpa-onnx/releases/download/v2.0.1/sherpa-onnx-2.0.1.aar).
  При отсутствии локальной копии Gradle скачивает только этот AAR с проверкой SHA-256.

```sh
python3 tools/asr.py prepare --downloads /папка/со/скачанными/файлами
./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest lintDebug
python3 tools/asr.py install --serial emulator-5554
python3 tools/asr.py check --serial emulator-5554
```

Нужны настроенные JDK/Android SDK, Python 3.10+ и `adb` в PATH
(либо `--adb /полный/путь/к/adb`). Для телефона заменить serial из `adb devices`.
`prepare` не скачивает файлы, проверяет SHA-256 и распаковывает в игнорируемую
папку `local-models`. `install` устанавливает основной APK и модели в
`Android/data/dev.wordbyword.app/files/models/gigaam-v2`.
Отсутствующие модели дают понятную ошибку в интерфейсе.

`check` запускает Android-тест основной сборки: два FLAC из репозитория,
тишина, 0,2 с аудио, отмена и отсутствие encoder. Он временно выключает сеть
эмулятора/телефона и восстанавливает её после проверки. Выходы сохраняются
в `local-models/asr-checks.json` и `local-models/network.txt`.

Лицензии sherpa-onnx (Apache-2.0), GigaAM и Silero (MIT), ONNX Runtime (MIT)
включены в APK: `assets/asr-notices.txt`. Источники и атрибуция тестового аудио —
[README набора](../test-data/diarization/README.md). WER на этих двух файлах
не измеряется: в наборе есть RTTM, но нет эталонного текста. Речь с наложениями
и точность слов требуют отдельной оценки; показатели эмулятора не заменяют телефон.

## Замеры

Android API 36 / x86_64, Pixel 6 AVD, Ryzen 5 5600H; сеть выключена.
Время включает декодирование файла, VAD, загрузку ASR и распознавание.

| Файл | Аудио | Обработка | RTF | Речевых фрагментов |
| --- | ---: | ---: | ---: | ---: |
| rec_0055.flac | 60 с | 17,156 с | 0,286 | 13 |
| rec_0273.flac | 60 с | 16,305 с | 0,272 | 16 |

Окна распознавания покрывают 100% и 97,46% эталонных речевых интервалов RTTM
соответственно; это покрытие речи с контекстом, не точность текста и не DER.
Пиковый RSS процесса на этих шагах: 633,5 и 673,7 МиБ (накопительный VmHWM);
PSS после обработки: 122,3 и 147,7 МиБ. Пик всего прогона с отменой — 828 МиБ.
Тишина 3 с и фрагмент 0,2 с дали пустой результат. Отмена на этапе ASR — 442 мс,
незавершённый результат не сохранён. Отсутствующий encoder дал понятную ошибку.
Временные PCM после всех сценариев удалены. Выходы — [asr-results.json](asr-results.json).
Проверки: 32 JVM-теста, сборки приложения/Android-теста и Lint — успешно;
Lint без ошибок, 28 предупреждений в существующих UI/проверочной Activity.
Локально использован установленный Gradle 8.14.4; wrapper 8.14.6 проверяется CI.
