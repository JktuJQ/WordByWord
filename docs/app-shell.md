# Основа Android-приложения

Первый этап [#10](https://github.com/JktuJQ/WordByWord/issues/10): Java/XML, библиотека записей, стенограмма и JSON-экспорт. Оформление временное; интеграция утверждённого дизайна — [#19](https://github.com/JktuJQ/WordByWord/issues/19), макеты — #18.

## Запуск и сценарии

Из корня проекта запустить телефон одной командой (devShell для неё не нужен):

```sh
nix run .#start-emulator
```

При первом запуске автоматически создаётся отдельный постоянный AVD: Android API 36, 1080×1920, 420 dpi, 2 ГБ RAM. Он хранится в `${XDG_DATA_HOME:-$HOME/.local/share}/wordbyword/android`; предыдущий тестовый профиль 320×640 в `/tmp` не меняется. На Apple Silicon используется ARM64-образ, на x86-64 — x86_64. Уже запущенный профиль повторно не запускается. Закрытие окна останавливает эмулятор, установленные приложения сохраняются. Для другого каталога можно задать `WORDBYWORD_ANDROID_HOME`.

После загрузки Android в другом терминале установить приложение:

```sh
nix develop --command ./gradlew installDebug
```

Открыть «Слово в слово» в списке приложений. Новый профиль изначально пустой; APK из старого тестового эмулятора туда автоматически не переносится. Если подключено несколько устройств, выбрать нужное через `ANDROID_SERIAL=emulator-5554` (актуальный номер посмотреть через `adb devices` в devShell).

Параметры эмулятора передаются после `--`, например:

```sh
nix run .#start-emulator -- -gpu swiftshader
```

Разрешение телефона и размер окна — разные параметры: AVD использует 1080×1920, плотность 420 dpi задаёт размер элементов Android; само окно можно растягивать мышью. Параметр `-scale` в текущем emulator устарел и игнорируется. Для изменения разрешения/плотности по умолчанию служат `hw.lcd.width`, `hw.lcd.height`, `hw.lcd.density` в launcher внутри `flake.nix`; изменения применяются при следующем запуске остановленного AVD. Настройки экрана не сбрасывают его пользовательские данные.

Если нужно больше места для содержимого при том же разрешении, можно уменьшить `hw.lcd.density`: например, с 420 до 360. Элементы займут меньше места относительно экрана телефона. Если мелким выглядит само окно на мониторе — увеличивать нужно окно, а не плотность Android.

1. Импортировать аудиофайл через системный выбор документов. Оригинал копируется в приватную библиотеку.
2. Открыть сохранённую стенограмму, если она уже есть: доступны просмотр, переименование участников и экспорт JSON.
3. Обработка новых файлов пока сообщает «Конвейер распознавания ещё не подключён». Фиктивные результаты и встроенный пример удалены.

Интернет и разрешение на доступ ко всему хранилищу не нужны. Импорт включает проверку читаемости и сохранение собственной копии; проверка кодека и подготовка PCM относятся к #4. Импортированные записи, готовые результаты и имена участников сохраняются в файловом репозитории и восстанавливаются после завершения процесса. Ошибки модели и выполнявшиеся задачи не возобновляются. Реализация и гарантии хранения описаны в [storage.md](storage.md); реальный ML-конвейер остаётся задачей #8.

## Разделение кода


| Файл / пакет | Ответственность |
| --- | --- |
| `MainActivity` | Жизненный цикл Activity, подключение экрана, системный возврат |
| `ui/AppController` | Навигация, изменение состояния библиотеки и передача команд обработке |
| `ui/audio/TranscriptPlayback` | Подготовка, воспроизведение, перемотка и освобождение MediaPlayer стенограммы |
| `ui/LibraryService` | Загрузка библиотеки, переименование и удаление через репозиторий в рабочем потоке |
| `storage` | Приватная копия аудио, версионированный JSON и атомарное сохранение |
| `ui/AppState` | Неизменяемый снимок библиотеки, выбранной записи и текущего состояния |
| `processing/ProcessingRunner` | Запуск `TranscriptionPipeline`, прогресс, отмена и сохранение через `TranscriptRepository` |
| `ui/view` | Отображение библиотеки, карточек и стенограммы; системные отступы |
| `ui/document/DocumentPicker` | Системные диалоги, их результаты и восстановление ожидающего экспорта |
| `ui/document/AudioDocuments` | Чтение метаданных и запись выбранного документа в рабочем потоке |
| `json/UtteranceJson` | Общая JSON-схема реплики, чтение и проверка таймкодов для хранилища и экспорта |
| `export/TranscriptJsonExporter` | Схема экспорта и преобразование `Transcript` в JSON через Gson |
| `WordByWordApplication` | Создание зависимостей, один рабочий executor, доставка обновлений в главный поток |
| `res/layout`, `res/values`, `res/drawable` | Временная компоновка, цвета, типографика, тексты и оформление |

Контроллер вызывается из главного потока; операции конвейера/репозитория — из рабочего. Подписка Activity действует только между `onStart` и `onStop`; контроллер не держит Activity после отписки. Состояние принадлежит Application, поэтому не привязано к пересозданию экрана. При отмене новый запуск ждёт фактического выхода старого вызова. Если отмена принята до сохранения, результат не сохраняется; после начала сохранения отмена уже не принимается. Дополнительных фоновых гарантий и foreground service нет.

На Android 13+ возврат обслуживает платформенный `OnBackInvokedDispatcher`; на старых версиях — `onBackPressed`. Подавление `GestureBackNavigation` относится только к необходимому старому callback, современный путь зарегистрирован отдельно. Старый callback помечен `@Deprecated`, как в Android API; подавление Java `deprecation` ограничено методом отступов для Android 8–10. Системные отступы обрабатываются с учётом API 26–36.

Для подключения настоящего конвейера заменить `TranscriptionPipeline` в `WordByWordApplication`. Сейчас он явно сообщает об отсутствии интеграции. Репозиторий уже сохраняет импорт и результаты; исполнение задач после завершения процесса относится к #8.

## Экспорт

JSON формирует [Gson 2.15.0](https://github.com/google/gson), лицензия Apache-2.0. Экспортёр явно создаёт JSON-объекты требуемой схемы; внутренние Java-модели не сериализуются через reflection. Экранирование и запись значений выполняет библиотека. Переданный `Writer` остаётся у вызывающего кода; `AudioDocuments` закрывает его после экспорта.

Экспортируются только `speaker_id`, `start_ms`, `end_ms`, `text` внутри массива `transcript`. Отображаемые имена не заменяют ID. Миллисекунды сохраняются целыми числами без округления до отображаемых секунд.

Если ID отсутствует, экспортёр назначает строку `unknown` всем таким репликам; при совпадении с реальным ID добавляет `_`, пока строка не станет свободной. Это техническая метка неизвестного, не вывод о принадлежности всех этих реплик одному человеку. Внутренний `Transcript` не меняется. Политика локальна для экспорта и покрыта тестом на коллизию.

Время с отрицательным началом или концом раньше начала отвергается. Ошибка записи не выдаётся за успех; провайдер документов может оставить неполный файл, о чём сообщается пользователю. Имя файла строится по ID записи. Для других форматов можно добавлять экспортёры, не меняя экранную модель и контракты обработки.

## Границы первого этапа

Реальные модели и сквозной конвейер ещё не подключены. Постоянная библиотека реализована файловым репозиторием; состояние остальных компонентов описано в их задачах. Для небольшого количества записей используются обычные XML-карточки внутри ScrollView; виртуализацию больших списков нужно добавить при работе с реальными длинными стенограммами.

Временная компоновка ориентирована на портретный экран. На маленьком экране в горизонтальной ориентации шапка и нижние кнопки занимают почти всю высоту. По решению владельца исправление оформления отложено до #19; состояние записей после поворота сохраняется.

Проверки: `./gradlew testDebugUnitTest assembleDebug lintDebug`. JVM-тесты проверяют отмену без сохранения, повторный запуск, ошибку обработки, замену подписчика, точную JSON-схему, экранирование, неизвестного участника, пустой результат и неверные интервалы. UI/системный выбор файла отдельно проверяются на Android.

История проверок хранения и ограничения приведены в [storage.md](storage.md). Старые проверки встроенного примера не подтверждают работу актуального ML-конвейера.

## Диагностика разработки

JDT LS использует экспериментальный импорт Android из Gradle. Чтобы Eclipse-компилятор находил `LambdaMetafactory` и `StringConcatFactory`, в `compileOnly` подключён поставляемый Android Build Tools файл `core-lambda-stubs.jar`. Путь вычисляется из SDK и версии Build Tools; классы не добавляются в APK и не заменяют Android runtime. После изменения зависимостей нужно дождаться обновления проекта в JDT LS.

Резервное копирование отключено через `allowBackup` для старых Android и явные `dataExtractionRules` для Android 12+: исключены файлы, БД, настройки и данные в device-protected storage, включая перенос на другое устройство.
