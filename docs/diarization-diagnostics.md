# Диагностика назначения говорящих, задача №33

Инструмент отделяет влияние границ фрагментов, эмбеддингов и выбора числа кластеров без ручного прослушивания.
Это исследование на компьютере, а не готовая замена Android-конвейера и не подтверждение скорости на телефоне.
Код извлечения признаков, кластеризации и оценки написан на Java.

## Данные и воспроизводимость

Протокол зафиксирован в [evaluation/diarization-diagnostics.json](../evaluation/diarization-diagnostics.json).
Он содержит 16 случаев длительностью до 300 секунд: 13 случаев с двумя–четырьмя участниками и три контроля с одним, пятью и семью участниками.
Два окна имеют длительность ровно 300 секунд.
Число участников включает даже короткие реплики на краю окна и проверяется при запуске.
Отбор сделан по исходным интервалам и числу участников, а не по результату нового алгоритма.

Источники — уже исследовавшиеся Dialogs и Veche.
Все случаи относятся к development; окна пересекаются, голоса и исходные реплики повторяются.
Увеличение числа файлов не увеличивает число независимых источников.
Независимой тестовой части в этом протоколе нет; выводы о неизвестных разговорах остаются предварительными.
Политика использования и лицензии сохраняются в SOURCE.md соответствующих наборов.

Для Veche читаются исходные WAV из кэша подготовки с проверенными SHA-256 upstream, а не перекодированные FLAC.
Для Dialogs проверяются SHA-256 составленных WAV и разметки.
Разметка читается без исправления по результатам модели.
Окна декодируются FFmpeg в PCM float32, 16 кГц, моно; длительность и хеш PCM сохраняются.
Пересекающие край окна реплики учитываются в общей оценке, но не используются как полные эталонные клипы для эмбеддингов.
Допуск в одну миллисекунду при проверке полноты нужен для округления исходных интервалов.

## Сравниваемые варианты

| Вариант | Границы | Число участников | Назначение |
| --- | --- | --- | --- |
| `baseline` | Полный sherpa-onnx | Автоматически, порог 0,8 | Текущая конфигурация |
| `reference_clips_threshold` | Исходные клипы из эталона | Average-linkage, порог 0,8 | Проверка признаков с известными границами |
| `reference_clips_known_count` | Исходные клипы из эталона | Задано по эталону | Диагностика ошибки выбора числа |
| `baseline_intervals_threshold` | Интервалы baseline | Average-linkage, порог 0,8 | Повторная кластеризация реальных фрагментов |
| `baseline_intervals_known_count` | Интервалы baseline | Задано по эталону | Потери при реальных границах с известным числом |

Average-linkage здесь является отдельной экспериментальной реализацией; она не объявляется точной копией внутренней кластеризации sherpa-onnx.
Кластеризация не ограничена диапазоном 2–4, но текущий оценщик поддерживает сопоставление не более 16 меток на запись и явно отказывает при превышении.
Варианты с эталонными границами или числом участников неприменимы непосредственно в продукте.
Нулевой DER при использовании эталонных интервалов не подтверждает качество поиска границ.

Эмбеддинг вычисляется из центрального непрерывного участка клипа длительностью не более восьми секунд.
Фрагменты короче 0,3 секунды не получают признака и остаются неназначенными в экспериментальном варианте.
Начальная кластеризация использует фрагменты от 1,5 секунды; затем доступные короткие фрагменты назначаются ближайшему центроиду.
Пропуски не заменяются ближайшей по времени репликой.
Метаданные источника определяют принадлежность клипа, но не гарантируют точные границы речи или отсутствие ошибки upstream.

## Проверка длительности и контроль центроидов

Для длительностей 0,3; 0,75; 1,5 и 3 секунды берутся одни и те же полные неперекрывающиеся клипы продолжительностью от трёх секунд.
Используется один центр клипа; сохраняются число подходящих реплик и представленных участников, попарные расстояния и назначение при известном числе кластеров.
Это длительность аудио, а не гарантированно непрерывной речи: в центре может оказаться пауза.
Вывод о влиянии длительности относится к этому способу извлечения и не доказывает единственную причину ошибок исходной схемы.

В отдельном `oracle_identity_enrollment` центроиды строятся с использованием эталонных ID.
Проверяемая реплика целиком исключается из построения своего центроида.
Для каждого запроса сохраняются решение и число пропусков из-за отсутствия другого опорного фрагмента того же участника.
Это диагностическая проверка различимости голосов с известными примерами, а не автоматическая диаризация.

## Метрики без подмены эталона

Основная дополнительная метрика — доля клипов с верной доминирующей меткой говорящего.
Для каждого эталонного клипа выбирается метка с наибольшим временем пересечения предсказаний; дублирующиеся интервалы одного говорящего не удваивают голос.
При равенстве голосов или отсутствии пересечений результат считается неназначенным и ошибочным.
Единое взаимно однозначное сопоставление ID максимизирует число верных клипов на всей записи.
Показываются ошибки коротких клипов менее двух секунд и полнота по каждому участнику с тем же сопоставлением.
Эта метрика не подтверждает точность каждого слова или границы внутри реплики и может скрыть частичную ошибку назначения внутри клипа.

Общая оценка содержит обрезанные краем окна клипы.
Для сопоставимого сравнения дополнительно сохраняется `full_turn_subset_attribution` на одном наборе полных клипов для всех вариантов.
Короткие клипы без признака продолжают входить в знаменатель этой метрики.
Проверка центроидов имеет собственную явно указанную область применимости и не смешивается с ней.

DER сохраняется по всей записи при радиусах исключения около эталонных границ 0; 0,125 и 0,25 секунды.
В отчёте поле называется `boundary_radius_seconds`: исключается именно ±указанный радиус.
Перекрытия учитываются, сопоставление ID для DER определяется независимо от метрики клипов.
Для каждого радиуса сохраняются составляющие DER и доля оставшегося эталонного времени участников.
Изменение рейтинга между радиусами означает чувствительность вывода к границам, а не основание выбрать наиболее удобный допуск.
Автоматические детекторы речи не используются для переписывания эталона или объявления спорных участков истинными.

Сводка объединяет ошибки по числу клипов и DER по эталонному времени участников, отдельно для целевых случаев и контролей.
Это описательные показатели на зависимых примерах, без доверительных интервалов.
Неполный отчёт не принимается сводкой; ошибка отдельного варианта запрещает его общую метрику.

## Запуск

Нужны JDK 21, FFmpeg, JVM JAR sherpa-onnx 2.0.1 и нативные библиотеки той же версии для текущей ОС.
JVM JAR и библиотеки указываются явно и не скачиваются инструментом.
Подготовка Dialogs и Veche описана в [evaluation/README.md](../evaluation/README.md).
Модели приложения готовятся обычной Gradle-сборкой.

```sh
./gradlew :evaluation:diarizationDiagnostics \
  -PsherpaJvmJar=/absolute/path/sherpa-onnx-jvm.jar \
  -PsherpaNativeDir=/absolute/path/native/lib \
  --args='evaluation/diarization-diagnostics.json evaluation/results/diagnostics-baseline app/src/main/assets/diarization/segmentation.int8.onnx app/src/main/assets/diarization/embedding.onnx ffmpeg'

./gradlew :evaluation:summarizeDiarizationDiagnostics \
  --args='evaluation/results/diagnostics-baseline/report.json evaluation/results/diagnostics-baseline/summary.json'
```

Для проверки одной записи добавляется её ID шестым аргументом; такой запуск не считается полным протоколом.
Для альтернативного эмбеддинга меняются только путь модели и выходной каталог.
По сохранённым признакам можно проверить один общий порог без повторного инференса и без передачи эталонного числа участников алгоритму:

```sh
./gradlew :evaluation:sweepDiarizationThresholds \
  --args='evaluation/results/diagnostics-baseline/report.json evaluation/results/diagnostics-baseline/thresholds.json 0.2,0.25,0.3,0.35,0.4,0.45,0.5,0.55,0.6,0.65,0.7,0.75,0.8'
```

Это подбор параметра на development, а не независимое подтверждение качества выбранного порога.
Сохраняются предсказанные интервалы и метрики каждого случая, включая контроли.
При исходном пороге 0,8 инструмент автоматически проверяет совпадение числа кластеров и количества верных полных клипов с исходным диагностическим прогоном.
При превышении возможностей оценщика вариант получает ошибку, а не улучшение среднего за счёт пропуска записи.

В отчёте сохраняются протокол, хеши входов, моделей, нативных библиотек, JVM JAR и исходников эксперимента, commit, Java, ОС и версия FFmpeg.
Результаты, признаки и промежуточные RTTM находятся в игнорируемом `evaluation/results/`.
Каждый случай записывается сразу после завершения; падение оставляет отчёт с `complete=false`.

Измеренное время baseline включает его загрузку моделей и обработку готового PCM.
Оно не включает Android-импорт, декодирование, ASR или сохранение и не является полным RTF приложения.
Эксперимент повторно извлекает эмбеддинги после полной диаризации и не предназначен для измерения ускорения новой схемы.
Цель RTF ≤ 0,5 проверяется отдельно на Android после выбора финалиста.

## Проверка изменений

```sh
./gradlew :evaluation:test
python3 -m unittest discover -s evaluation/scripts/tests
```

## Результат 8 ноября 2026

Выполнены два полных прогона по 16 случаям на macOS arm64, sherpa-onnx JVM/JNI 2.0.1, CPU, один поток.
Проверены штатный ERes2Net base zh-cn и ERes2Net VoxCeleb en; сегментация pyannote int8 одинакова.
Физический Android-телефон не подключён; обнаружен только эмулятор.
Все показатели ниже относятся к development и предварительным эталонам.

Два последних порога выбраны по максимальной доле верных полных клипов на этих же development-случаях из сетки 0,2–0,8 с шагом 0,05.
Это подбор на данных, а не независимое доказательство улучшения.
Число участников в этих двух алгоритмах не передаётся из эталона; границы происходят из полного sherpa-прогона с соответствующим эмбеддингом.
Кандидаты повторно выполняют дорогие вычисления и ещё не интегрированы в приложение.

На двух пятиминутных файлах кандидат VoxCeleb с порогом 0,45 дал:

| Запись | Текущее решение: клипы, число | Кандидат: клипы, число | DER текущего / кандидата, радиус 0 |
| --- | --- | --- | --- |

Кандидат не готов к выбору по одному среднему.
На Dialogs MD он создаёт четыре кластера вместо двух и ухудшает назначение с 12/12 до 11/12.
На контролях с пятью и семью участниками он даёт три и пять кластеров; их DER составляет 48,68% и 36,13% против 42,41% и 30,84% у штатного решения соответственно.
Для точных исходных значений следует использовать машинную сводку по ссылке ниже.

Диагностические результаты объясняют направление дальнейшей работы:

- С эталонными полными клипами и известным числом участников оба эмбеддинга дают 253/254 верных назначений на целевых случаях.
- Проверка центроидов с эталонными ID и исключением запроса даёт 253/253 на подходящих целевых репликах у обеих моделей; это использует эталонные ID и не является автоматической диаризацией.
- На одних и тех же 180 подходящих клипах при известном числе участников длительность 0,3 секунды даёт 125/180 у штатного эмбеддинга и 123/180 у VoxCeleb; три секунды дают 180/180 и 179/180 соответственно.
- На реальных интервалах с известным числом участников получается 234/254 и 235/254; границы и состав фрагментов остаются существенным источником потерь.

Замена эмбеддинга помогает на этом наборе, но не решает автоматически определение числа участников.
Сначала нужно улучшить автоматическую остановку кластеризации и устойчивость назначения коротких фрагментов, сохранив контроль регрессий на каждом источнике.
Предположение, что один глобальный порог принципиально невозможен, этим экспериментом не доказано; проверенный общий порог улучшает среднее, но остаётся неустойчивым между записями.

Исходники старых прототипов в `/tmp/sherpa-jvm` и незакоммиченные пользовательские изменения сохранены.
Проверки: 41 JVM-тест, семь Python-тестов подготовки, оба полных диагностических прогона и документированная Gradle-команда на одиночном контроле прошли.
Рабочая конфигурация Android-приложения не изменена.

## Второй этап: автоматическое число участников

Добавлены Java-критерии максимального силуэта, максимального абсолютного разрыва высот average-linkage и спектрального разрыва нормализованного лапласиана.
Ни один из них не получает эталонное число участников и не ограничивает результат диапазоном 2–4.
Силуэт и разрыв объединений используют отдельный проверяемый порог максимального попарного расстояния для случая одного голоса; проверены значения 0,15; 0,25 и 0,35.
Опорные фрагменты проверены при минимальной длительности 1,5; 2,5 и 3,5 секунды.
Проверяемые короткие фрагменты сохраняются и назначаются центроидам, а не удаляются из оценки.

Спектральный эксперимент строит симметричный граф ближайших соседей с весами положительной косинусной похожести, нормализованный лапласиан и выбирает число по максимальному разрыву собственных значений.
Проверены доли соседей 0,1; 0,2; 0,3 и 0,5.
Затем используется прежняя average-linkage с найденным числом: это эксперимент по выбору числа, а не полный спектральный конвейер или порт NME-SC.
Мотивация спектрального подхода описана в [работе Park et al.](https://arxiv.org/abs/2003.02405); показатели авторов на других наборах не относятся к нашей реализации.
Собственные значения вычисляются на Java методом вращений; тесты сверяют известные спектры симметричных матриц и разделение одного, двух, трёх, четырёх и семи голосов.

На реальных интервалах VoxCeleb получены:

| Критерий | Верные полные клипы | Верное число участников | DER, радиус 0 |
| --- | ---: | ---: | ---: |
| Общий порог 0,45 | 231/254 | 9/13 | 10,32% |
| Силуэт, опора 1,5 секунды | 193/254 | 7/13 | 25,39% |
| Разрыв объединений, опора 1,5 секунды | 193/254 | 7/13 | 25,39% |
| Спектральное число, доля соседей 0,2 | 230/254 | 10/13 | 10,75% |

Доля соседей 0,3 даёт тот же результат, 0,1 и 0,5 — хуже.
Увеличение минимальной длительности опоры не улучшило силуэт и разрыв объединений.
На эталонных границах эти критерии существенно лучше, чем на реальных, поэтому их успех с оракулом не переносится автоматически в приложение.

Спектральный вариант исправляет число участников в Dialogs MD и пятиминутном Auth incident.
На обеих пятиминутных записях число определено верно: три и четыре; верно назначены 74/84 и 31/32 полных клипа.
Однако он ухудшает окно B2B SaaS с четырьмя голосами до трёх и 12/15 верных назначений вместо 15/15.
Контроль с одним голосом разделяется на два, а контроли с пятью и семью голосами — на три.
Поэтому спектральный вариант не выбран заменой действующего алгоритма.

Проверено ретроспективное исключение групп Dialogs и Veche из подбора правила.
При подборе на Veche выбирается общий порог: на Dialogs он даёт 33/36 и верное число в 2/3 случаях.
При подборе на Dialogs выбирается спектральное число: на Veche оно даёт 196/218 и верное число в 7/10 случаях.
Суммарно получается 229/254, что не подтверждает устойчивого преимущества над общим порогом 0,45.
Это дополнительная диагностика development: обе группы уже использовались раньше, поэтому независимым тестом такое исключение не является.

Полные результаты находятся в `automatic-count.json`, `automatic-count-anchors.json` и `spectral-count.json` каталога `evaluation/results/diagnostics-v2-voxceleb/`.
Пример воспроизведения:

```sh
./gradlew :evaluation:sweepDiarizationThresholds \
  --args='evaluation/results/diagnostics-v2-voxceleb/report.json evaluation/results/diagnostics-v2-voxceleb/spectral-count.json spectral@0.1,spectral@0.2,spectral@0.3,spectral@0.5,0.45,0.8'
```

Синтаксис `silhouette@0.25@2.5` и `gap@0.25@2.5` задаёт критерий, порог для одного голоса и минимальную длительность опоры.
У спектрального варианта параметр после `@` означает долю соседей, а не косинусный порог.
Проверены 47 JVM-тестов и воспроизведение прежнего порога 0,8 по сохранённым признакам.
Надёжный автоматический выбор числа участников на всех целевых случаях пока не достигнут; остаётся совместно учитывать чистоту фрагментов и устойчивость кластеров, а не выбирать число только по одному скалярному критерию.

## Третий этап: полноценная спектральная группировка

Вместо одной оценки числа добавлены собственные векторы лапласиана, нормализация строк спектрального представления и k-means в этом пространстве.
Используются три детерминированные инициализации k-means; выбирается наименьшая сумма квадратов расстояний, эталон в выборе не участвует.
Опорные фрагменты сохраняют спектральные метки; короткие фрагменты назначаются центроидам в исходном пространстве голосовых признаков.
Это экспериментальная реализация, не полный NME-SC и не обученная модель кластеризации.

Для быстрой итерации доля соседей зафиксирована на ранее проверенном значении 0,2.
Аудио и эмбеддинги не вычислялись повторно; сравнены только два уже сохранённых эмбеддинга и три способа группировки.

| --- | ---: | ---: | ---: |
| VoxCeleb, average-linkage, порог 0,45 | 231/254 | 9/13 | 10,32% |
| VoxCeleb, спектральное число + average-linkage | 230/254 | 10/13 | 10,75% |
| VoxCeleb, полная спектральная группировка | 231/254 | 10/13 | 10,82% |

Разница между двумя эмбеддингами при полной спектральной группировке мала на этом наборе; подтверждённого универсального преимущества одного из них нет.
Смена самой группировки полезнее штатному эмбеддингу, но оставшиеся ошибки числа почти совпадают у обеих моделей.
Оба спектральных варианта разделяют одиночный контроль на два и недооценивают число голосов в контролях с пятью и семью участниками.
Результат не является основанием менять приложение по одному среднему development-показателю.
Следующий эксперимент следует направить на состав опорных фрагментов и сохранение редкого участника, а не на очередной широкий перебор моделей и параметров.

Воспроизведение: в аргументе перебора указываются `spectral-full@0.2,spectral@0.2,0.45` для VoxCeleb или `spectral-full@0.2,spectral@0.2,0.5` для штатного эмбеддинга.
Проверены шесть целевых спектральных тестов, включая невязку собственных векторов и сохранение отдельных голосов после полного шага группировки.

## Четвёртый этап: смешанные опорные фрагменты

Проверен VoxCeleb с зафиксированным общим порогом 0,45; нового инференса и подбора порога не было.
Профиль строится отдельно по всему интервалу и по центральному участку до восьми секунд, из которого реально извлекался эмбеддинг.
Фрагмент считается строго смешанным при любом пересечении его участка эмбеддинга с несколькими ID источника.
Для устойчивого варианта из эталонных клипов исключаются окрестности границ ±0,125 секунды; существенным смешиванием считается не менее 0,2 секунды второго голоса внутри оставшихся интервалов.
Это диагностическое правило по предварительной разметке клипов, а не независимо подтверждённое присутствие двух голосов в аудио.
Неизвестные и спорные участки не объявляются правильным эталоном.

На 13 целевых случаях найден 291 фрагмент с эмбеддингом, из них 251 опорный.
Существенно смешаны 22 опоры, ещё шесть опор затрагивают только более слабое или пограничное смешивание.
Все исходные фрагменты, включая смешанные и короткие, сохранены в назначении и оценке.

| Диагностическое вмешательство | Верные полные клипы | Число участников верно | DER, радиус 0 |
| --- | ---: | ---: | ---: |
| Без вмешательства | 231/254 | 9/13 | 10,32% |
| Исключить смешанные опоры только из центроидов, сохранить исходные группы | 231/254 | 9/13 | 10,48% |
| Исключить существенно смешанные опоры и заново кластеризовать опоры | 234/254 | 11/13 | 9,29% |

При очистке центроидов группа без чистой опоры сохраняет исходный центроид; число таких случаев явно записывается.
На целевых записях такой возврат потребовался одной группе в пятиминутном Auth incident.
Строгая и устойчивая очистки центроидов дали одинаковое число верных клипов.
Перекластеризация использует эталон только для отбора опор и не получает правильное число участников, но без автоматического отбора в приложение она неприменима.

Разбор исходных ошибок использует одно глобальное сопоставление ID на запись:

- Ошибочны 23 из 254 полных исходных клипов.
- Среди коротких клипов менее двух секунд ошибочны 12 из 33, среди остальных — 11 из 221.
- Смешанные полные интервалы затрагивают 64 исходных клипа, из которых ошибочны 20.
- Существенно смешанные участки эмбеддингов затрагивают 51 исходный клип, из которых ошибочны также 20.
- Остальные 190 клипов, пересекающиеся только с интервалами одного исходного голоса, содержат три ошибки.

Категории пересекаются, а пересечение со смешанным интервалом само по себе не доказывает причинность.
Сопоставление преобладающего голоса участка эмбеддинга с назначением ошибается только на пяти из 291 фрагмента; это не точность диаризации, поскольку меньшая реплика другого участника внутри длинного фрагмента может быть потеряна при верном преобладающем голосе.
Разложение по исходным клипам автоматически сверяется с общей метрикой назначения для каждой записи.

Массовое загрязнение центроидов не подтвердилось как главная причина: их очистка не улучшила назначение.
Смешанные опоры влияют на кластеризацию умеренно: помощь эталона дала три дополнительные правильные реплики.
Следующий узкий эксперимент — выделять потерянные короткие смены говорящего внутри текущих интервалов, а не снова менять только центроиды или модель эмбеддингов.
Необходимо проверить доступность локальных сигналов сегментации до глобального объединения говорящих.

Воспроизведение:

```sh
./gradlew :evaluation:anchorContamination \
  --args='evaluation/results/diagnostics-v2-voxceleb/report.json evaluation/results/diagnostics-v2-voxceleb/anchor-contamination.json'
```

Пройдены три целевых теста: отличие полного интервала от фактического участка эмбеддинга, устойчивость к неточности границы и объединение повторяющихся интервалов одного голоса.
Исходный результат воспроизведён по назначению, числу участников и DER для всех 16 случаев, включая контроли.
Сводка с решениями по клипам: [diarization-33-anchor-contamination-2026-11-08.json](../artifacts/test-results/diarization-33-anchor-contamination-2026-11-08.json).
Приложение и эталоны не изменены.
