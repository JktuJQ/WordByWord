# Дизайн приложения по PDF

Ветка `feature/19-design-main` создана поверх актуального `main` после слияния каркаса приложения. Визуальный ориентир — предоставленный UX Pilot PDF от 6 ноября 2026 года. При расхождении с временным оформлением каркаса приоритет отдан макетам пользователя.

Реализованы состояния библиотеки: пустой список, карточки готовых и обрабатываемых записей, поиск по названию, режим выбора, подтверждение удаления из текущего списка и отправка списка названий. Нижняя панель добавления открывает выбор файла или запись с микрофона. Запись с микрофона позволяет начать, приостановить, продолжить и завершить запись, прослушать результат, назвать его и передать в существующий конвейер импорта. В стенограмме показаны участники, реплики и таймкоды; имя участника можно изменить через существующий контракт хранилища. Для стенограммы с доступным исходным аудио подключены запуск и перемотка на пять секунд. Экспорт JSON оставлен из каркаса.

Ограничения текущей ветки: из `main` пока не поступает реальное распознавание и диаризация для импортированного аудио. Демонстрационная стенограмма остаётся только примером интерфейса без звука. Хранилище заменено файловым репозиторием из #9: импорт, результаты, переименование и удаление сохраняются после перезапуска; гарантии описаны в [storage.md](storage.md). Отправка в режиме выбора передаёт названия, не аудиофайлы. Эти ограничения относятся к незавершённым задачам обработки и постоянного хранения; дизайн не выдаёт их за готовый MVP.

Проверки: `assembleDebug`, `testDebugUnitTest`, `lintDebug` прошли с JDK 21 и Android SDK 36. На эмуляторе API 37 проверены пустая библиотека, карточка записи, переход в экран записи и работающий таймер микрофона. Полный сценарий импорта и реальной стенограммы требует интеграции ML и постоянного хранилища. Перед закрытием задачи нужны сравнение с утверждённой Figma и проверка на целевом Android-устройстве.
