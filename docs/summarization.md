# Краткое содержание

Дополнительная функция поверх готовой стенограммы.
Кнопка «Подытожить» открывает экран с действием «Создать краткое содержание».
Результат можно выделить и скопировать; исходный текст и экспорт JSON не меняются.
Используется выбор дословных выдержек: модель выбирает ключевые фрагменты, а не переписывает разговор.

## Модель

Qwen3-0.6B INT4 no-think запускается на CPU через LiteRT-LM Android 0.17.1.
Источник: [litert-community/Qwen3-0.6B-int4](https://huggingface.co/litert-community/Qwen3-0.6B-int4).
Ревизия — `56621f0115eba5781051ef9714c06e16e6d40c0b`.
Файл — `qwen3_0.6b_nothink_q4_block32_ekv1280.litertlm`, 347251840 байт.
SHA-256 — `2df6821ec12702dafd33915e7a1a1adc7c4b053f3672fd9555dfaf3a114c4139`.
Лицензия Apache-2.0 включена в `assets/summary/LICENSE`.

Задача Gradle `prepareSummaryModel` получает и проверяет веса перед сборкой.
Модель входит в APK и при первом запуске функции копируется в приватный каталог без резервного копирования.
Для работы интернет не требуется.
К размеру установки добавляются веса, runtime и приватная копия модели.

## Выполнение

Генерация использует тот же последовательный исполнитель, что и основной конвейер.
Одновременный запуск суммаризации и обработки аудио блокируется контроллером.
Движок загружается один раз на операцию и закрывается при завершении, отмене или ошибке.
Пересоздание Activity не запускает генерацию повторно; состояние принадлежит Application.

Текст разбивается по пробельным границам на части не более 512 байт UTF-8, длинное слово разделяется без потери символов.
Это консервативный бюджет для контекста 1280 токенов, включая короткую инструкцию, нумерацию фрагментов, шаблон чата и ответ до 32 токенов.
Каждая часть обрабатывается в отдельном диалоге, без накопления истории.
Часть разбивается на предложения и строки, не более 16 нумерованных фрагментов.
Модель возвращает до трёх номеров; неизвестные номера и свободный текст отклоняются.
В результат попадают только соответствующие дословные фрагменты в исходном порядке.
Экран показывает номер текущей части и позволяет отменить операцию.
Текст всех частей включается в обработку; готовые конспекты выводятся последовательно с номерами частей.
Единое повторное обобщение не выполняется.

Готовый результат сохраняется атомарно в `summary.json` рядом с записью.
Ключ учитывает текст, отображаемые имена участников и версию алгоритма.
При повторном открытии используется сохранённый результат; изменение текста или имён требует нового конспекта.
Удаление записи удаляет также сохранённое содержание.
Отмена или ошибка не сохраняют частичный ответ.
Прерванная завершением процесса операция автоматически не возобновляется.

## Качество и проверки

[Прототип PR #55](https://github.com/JktuJQ/WordByWord/pull/55) подтвердил вызов модели из Java на эмуляторе.
Он также выявил пропуски и искажения фактов на русских разговорах.
Эта интеграция не заявляет улучшения качества модели.
Свободная генерация в первом прогоне этой интеграции также исказила отрицание; этот вариант заменён выбором исходных выдержек.
На экране явно указан дословный выбор фрагментов моделью.
Короткие части ограничивают общий контекст; выбор может пропустить важное, а отдельные выдержки — потерять связь с соседними частями.
При разбиении предпочтительны границы предложений и реплик; длинные предложения могут разделяться на несколько частей.
Промпт интеграции отличается от исследовательских промптов; прежние замеры времени и качества не являются измерениями этой версии.

Перед сдачей проверить на телефоне:

1. Генерацию короткой стенограммы без сети.
2. Длинную стенограмму с фактами в начале, середине и конце.
3. Отмену, повторный запуск и поворот экрана.
4. Повторное открытие после перезапуска приложения.
5. Переименование участника и обновление содержания.
6. Невозможность одновременного запуска обработки аудио и суммаризации.
7. Пиковую память, время и фактическую точность содержания.

Функция добавляется отдельным коммитом поверх main и может быть полностью удалена его откатом.

## Совместимость сборки

Сборка разрешает транзитивные Kotlin stdlib/reflect 2.4.0, требуемые LiteRT-LM.
Существующий анализатор lint ожидает metadata 2.2 и печатает сообщения о несовместимой версии, хотя задача завершается успешно.
Версии транзитивных библиотек принудительно не понижаются.
Это ограничение инструментов анализа, отдельно от проверки реального запуска APK.

Веса готовятся в `app/build/generated/summaryAssets/`, подключённом как отдельный источник assets.
После отката коммита этот источник перестаёт упаковываться, даже если локальный файл модели остался в build.
