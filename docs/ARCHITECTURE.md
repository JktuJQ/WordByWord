# Архитектура

WordByWord — Android-приложение на Java/XML для обработки импортированных аудиозаписей без сети.
Исходный код находится в [app/src/main/](../app/src/main/), проверки качества — в отдельном JVM-модуле [evaluation](../evaluation/README.md).
Модуль evaluation не включается в APK.

## Путь данных

1. Системный выбор файла передаёт URI приложению, а файловый репозиторий сохраняет приватную копию записи.
2. `AppController` запускает `LocalTranscriptionPipeline` и передаёт прогресс в интерфейс.
3. `AndroidAudioPreparer` декодирует запись через Android MediaExtractor/MediaCodec, сводит каналы в моно и подготавливает PCM 16 кГц.
4. `SherpaSpeechRecognizer` использует Silero VAD и GigaAM v3 RNNT int8 с пунктуацией, а `SherpaOnnxSpeakerDiarizer` получает интервалы участников.
5. `OverlapTranscriptAssembler` сопоставляет ASR-фрагменты с интервалами участников и формирует `Transcript`.
6. Репозиторий сохраняет результат, интерфейс показывает реплики, а `TranscriptJsonExporter` создаёт внешний JSON.

Аудио обрабатывается на Android; облачных API для распознавания и диаризации в основном сценарии нет.
Модели и JNI-библиотеки sherpa-onnx 2.0.1 включаются в APK при сборке.

Краткое содержание запускается отдельно поверх готовой стенограммы через Qwen3-0.6B INT4 и LiteRT-LM 0.17.1.
`SummaryRunner` управляет операцией, `LocalSummarizer` обрабатывает текст частями, `SummaryStore` сохраняет результат рядом с записью.
Суммаризация использует последовательный исполнитель основного конвейера и не запускается одновременно с обработкой аудио.
Исходная стенограмма и внешний JSON остаются без изменений.
Подготовка модели, ограничения и проверка описаны в [summarization.md](summarization.md).

## Исполнение и хранение

Контроллер, исполнители и репозиторий принадлежат `WordByWordApplication`.
По умолчанию ASR и диаризация работают параллельно; флаг сборки `-PparallelInference=false` включает последовательный вариант.
Файловые операции и вычисления выполняются вне UI-потока.
Хранилище использует отдельную папку на запись и JSON версии 2 с чтением прежнего формата v1.
Внутренний JSON хранения и обязательный внешний JSON экспорта имеют разные назначения.
